# Cross-genre video asset library

This is the shared asset pool for future videos, not a collection dedicated to the self-improvement channel. It separates three classes so later projects can reuse resources without guessing at rights:

1. **Bundled / redistributable** — original assets generated by this repository and source packs whose public page explicitly identifies the pack as CC0. Each downloaded item gets a provenance record and SHA-256.
2. **Use-in-video, source-only** — free stock footage, music, and other media whose terms allow incorporation into a finished film but prohibit redistributing the raw files as a standalone pack. The source URL and restrictions live in the catalog; the builder does not download these into our release ZIP.
3. **Review required** — anything with a non-CC0 license, unclear provenance, people/brand restrictions, or license metadata that cannot be confirmed. Do not bundle automatically.

- Up to 60 The Met Open Access images, after checking each object's `isPublicDomain` flag; each record retains the official object/image URL and metadata.
- Up to 160 Wikimedia Commons images whose individual file metadata says CC0 or Public Domain; CC BY/SA, noncommercial, unclear, or missing rights are skipped.
- Up to 45 Wikimedia Commons SVG vectors (maps, science diagrams, transit layouts, botanical illustrations, patterns and engineering schematics) when the exact file metadata says CC0 or Public Domain. Each SVG is sanitized to remove scripts, event handlers, and remote references before indexing.
- Up to 20 short video/audio files from Wikimedia Commons, subject to strict file-level CC0/Public Domain metadata, host, byte-size, MIME and container checks. Video and audio counts appear in the build manifest; if no suitable small files are found, the report says so rather than pretending the source yielded media.
- Up to 60 Rijksmuseum Open Access artwork images, downloaded through the no-key OAI-PMH feed and official IIIF image service only when the individual EDM record explicitly carries CC0 or Public Domain Mark rights.
- Up to 60 Smithsonian Open Access images from the official API, with a strict two-level gate: both the item metadata and the exact media file must say CC0. A `SMITHSONIAN_API_KEY` GitHub Actions secret is optional but recommended; without it, the build makes a low-volume attempt using `DEMO_KEY` and records any authentication/rate-limit failure.
- NASA Image and Video Library items: screened small images, short video clips and audio files from NASA-center records. The NASA lane is **not CC0**; it retains NASA’s media usage guidance, attribution requirements, logo/endorsement warnings and item-level source.
- Library of Congress images only when the specific record carries an explicit positive rights statement (e.g. “No Known Restrictions on Publication”); ambiguous or conflicting rights records are skipped.
- Openverse CC0 images/audio where the live API responds; transient API failures are recorded and do not block the more stable sources.
- Larger Poly Haven selection: up to 16 HDRIs, 22 models and 36 texture packages; bundle available models/dependencies and PBR maps (base color, normal, roughness, AO/displacement where available). Item/source metadata and SHA-256 are retained.
- 125 original procedural sound-effect WAV presets for UI, foley-like accents, multiple weather/forest/ocean/city ambiences, camera, heartbeat, tension, science-fiction, magic, transitions and impacts. These are synthesized by code, not copied recordings.
- 34 original tileable SVG surface textures for blueprint grids, contours, paper, concrete, marble, metal, carbon fiber, wood grain, textiles, circuits, halftones, ocean patterns and retro looks.
- `ASSET_CATALOG.html` — searchable offline catalog with image/video previews and audio players, category filtering, direct file links, and source/license links.
- `ASSET_INDEX.json`, `SOURCES_AND_LICENSES.md`, and `SHA256SUMS.txt`.

The workflow fails before source downloads if the offline rights tests fail, verifies every generated MP4's codec/resolution/duration, and matches the motion-loop manifest count against real indexed files.

The GitHub Actions workflow runs offline license-gate regression tests before making external requests, then validates the new media counts against actual indexed entries.

Large binary assets are shipped as a GitHub Release asset, not ordinary Git blobs. Open the [builds and downloadable releases](https://github.com/Nolane-x/video/releases) and download `video-asset-library.zip`; open `ASSET_CATALOG.html` after extraction to browse offline. Run metadata/checksum reports are also attached to each Actions run for 30 days.

## New source and rights rules

- **Smithsonian:** only images that are explicitly CC0 both at the collection record and at the selected media object are bundled. The API may require a registered key for reliable usage; API failures are recorded, not represented as zero uncertainty.
- **Rijksmuseum:** only item-level CC0/Public Domain Mark images are bundled. Source record, creator, exact rights statement and IIIF image URL stay in the manifest. Other rights, including culturally sensitive context or trademarks, must still be reviewed.
- USGS and NOAA are documented as future source lanes, not claimed as downloaded automatically; their official guidance says public-domain status can have item-level exceptions and credit/endorsement rules.

- NASA media is tracked under NASA’s own media-use guidance and **must not** be labelled CC0. Keep NASA attribution, never imply NASA endorsement, avoid logos/seals, and check identifiable-person/privacy/publicity constraints.
- Library of Congress photos are auto-bundled only if the item-level rights statement is explicitly positive and non-conflicting. The user remains responsible for context and other rights.
- The Met and Wikimedia continue to use per-item Public Domain/CC0 checks. Smithsonian Open Access is recorded as a future high-value source but is not fetched until an API key and item-level CC0 verification can be configured safely.
- Exact successful download counts are generated into each `ASSET_INDEX.json`; API timeouts and skipped records are not represented as successful downloads.

## Usage

Use `GENRE_PLAYBOOK.md` to select a visual language first, then search by category and combine only assets that help the story. Do not make every film look alike by swapping the title over the same background. Mix source media, purpose-built environments, real 3D models, diagrams, and custom composition when the genre calls for them.

The download workflow is intentionally rate-limited and size-capped. A partial third-party failure should show in the index; it must never be reported as a complete pack unless checksums and counts confirm it.
